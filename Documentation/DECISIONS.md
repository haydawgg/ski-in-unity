# Decisions

- 2026-09-29: Adopt PowderFlow from the new master plan; preserve the existing project path and installed Unity 6000.3.25f1.
- Use URP and the Input System. Keep generated geometry deterministic and use Blender FBX exports. Temporary geometry is limited to the early physics milestones.
- Linux is the development and first shipping target because this workstation runs CachyOS. Other build targets require their Unity Hub modules.
- Each milestone is gated by batch compilation and automated checks, with simulation runs and captured frames for gameplay/visual inspection. Subjective feel cannot be certified by a headless test; document that limit explicitly.
- Snow and sky use original URP HLSL source shaders instead of generated Shader Graph JSON; material parameters and GraphicsConfig remain editable. This differs from the plan's authoring format while implementing its visual effects.
- Historical M9/M10 method: separate render benchmarks from gameplay FPS. Unity test coroutine iterations run faster than rendered frames in batch mode; camera rendering plus GPU readback is used for M9 and standalone unscaled frame timing for M10.
- Correct Blender export coordinates for Unity's imported X reflection; verify left/right rig placement and off-center analytic terrain height after every regeneration.
- Select Unity's native Wayland backend in the portable launcher when a Wayland session is detected. Default X11 stalled before scene initialization on this workstation; native Wayland completed visible gameplay and menu captures. Keep an explicit X11 opt-out for other desktops.
- Deliver a Linux development build with original procedural Foley and coordinated outfit presets. Document remaining authoring-format/content differences and human playtest requirements in FINAL_REPORT rather than claiming automated checks certify subjective feel.
- Execute visual polish in seven committed phases, starting with rendering correctness. Persist Volume effects as subassets, assign URP post resources, retain fog variants in player builds and inspect native captures before marking the foundation complete.
- Canonicalize Blender material suffixes on import and distinguish terrain snow/rock blending from snow on props and vegetation. This prevents numeric material names bypassing the custom snow shader and keeps steep tree caps/jump sides snowy.
- Neutralize injected simulation input and isolate virtual gamepad devices from real input/focus in tests. These changes make captures and gameplay regression runs reproducible without changing skiing force/tuning values.
- Historical VP1/VP2 method: run capture/profile diagnostics in the background and record frame-time percentiles. Discard timed-out launches and stale output; keep short native-player measurements separate from GPU-flushed camera benchmarks and future dense-region/action profiling.
- VP2 uses original lofted clothing with blended elbow/knee/torso weights, consolidated into one clothing renderer and four equipment renderers. Preserve the existing humanoid-compatible bone names, left/right convention, 1.7 m twin tips and physics colliders.
- Put character pose, garment/equipment light response and coordinated outfit palettes in CharacterVisualConfig, referenced through AssetCatalog. Use a restrained ambient floor and rim in the skier shader to retain backlit silhouette detail.
- Review every grab from front, side and rear and measure wrist-to-grip error. Fold Mute/Japan legs more tightly and bring the Nose grip up to the reaching hand. These remain stylized procedural poses, rather than a claim of anatomical or reference-video accuracy.
- Reset ski local positions before applying each pose to prevent grounded contact alignment carrying offsets into flight. Trail poles away from the hand's actual side during cross-body grabs. Expand skinned bounds and update them offscreen so independently posed equipment stays visible.
- VP3 uses seeded asymmetric branch whorls and snow lobes, consolidated into one mesh per pine LOD. Preserve the branch layout across reductions, crossfade for 0.3 seconds and support the same dither in the custom snow shader. Keep trunk capsules; shrubs and distant ranges are noncolliding visual assets.
- Compose scenery in MountainScenery using WorldConfig region weights, scale ranges, spacing and ridge layers. Keep a broad easy start, denser park edges, an open big-air vista, freeride gaps and a calmer lower run. Reserve the central route, powder corridor, side-feature approaches, lift and fence space before accepting placements.
- Regenerate scenery separately from riding terrain. Retain and compare hashes for all ten mountain FBXs, keep physics tuning unchanged, and rerun seam/clearance/descent checks. Bury ridge skirts and blend the noncolliding lower-valley backdrop into the mountain edge.
- Disable shadow casting on distant backdrop meshes. The enlarged ranges initially shaded almost the entire lower run at sunset; nearby terrain, trees, rocks and props retain their shadows, while the backdrop supplies silhouettes and depth without hiding the skier or snow.
- Native region captures select their lighting explicitly and record spawn coordinates/initial speed. The shallow powder ripple at z=1060 did not meet the general distance gate even with incoming momentum; capture the continuous descent from x=75/z=1120 with recorded 15 m/s incoming speed. Retain the distance gate, original powder drag/friction and gameplay behavior.
- User preference (2026-09-29): cap all runtime sessions at 144 FPS with VSync disabled, including editor Play mode and diagnostic launches. Remove timed render benchmarks, frame-time collection and FPS success gates. Use targeted behavioral/visual checks and one final launch/package check; profile only for a concrete issue or an explicit request.
